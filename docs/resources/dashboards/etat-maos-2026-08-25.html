04Les 3 enjeux pour utiliser MAOS pour de vrai

Ta frustration exacte — « je ne peux toujours pas m'en servir » — se résout dans cet ordre :

Finir la mémoire centralisée L

Réparer le pont → ré-indexer → trier/re-distiller les 281 fiches → brancher la promotion. À la fin : tout ce que tu ingères (cours, notes, repos) devient trouvable par chaque agent, dans chaque mission. C'est la « grosse base bien finie » que tu demandes — et le prérequis du vault de notes.

Livrer les 4 cartes du lot 1 (C3 → C10 → C9 → C4) 4 × M

Ensemble, elles transforment MAOS en outil de confiance : un rapport honnête par mission, une reprise en 1 clic après un crash, la preuve de ce qu'un agent a écrit chez un projet externe, et un prompt de secours copiable. Sans elles, piloter un vrai projet reste de l'artisanat.

Brancher la couche live (Étape 1) L

Le jour où le chat du cockpit parle au vrai moteur, MAOS cesse d'être une maquette pilotée depuis le terminal : tu lances une mission depuis l'interface, tu regardes les agents travailler, tu valides les gates. C'est le moment « je m'en sers ».

05Lancer la pile — 3 commandes

Depuis la racine du repo (Node ≥ 20, pnpm). Le cockpit s'ouvre sur localhost:3000, le worker tourne à côté.

# 1. base (première fois ou après un pull avec migrations)
pnpm db:migrate && pnpm db:seed

# 2. tout démarrer (cockpit + worker en parallèle)
pnpm dev

# 3. santé de la mémoire (retrieval + binaires d'extraction)
pnpm mem:doctor

Vérifier que tout va bien : pnpm -r test (843 verts attendus) · pnpm lint (4 portiques) · pnpm smoke (35 parcours navigateur).

07La méthode de travail (pour ne plus s'égarer)

Règles de reprise — gravées après l'audit

  • Une session = un projet. MAOS se construit dans MAOS ; find_location_Paris et les autres se pilotent dans leurs propres sessions. Jamais les deux dans la même conversation.
  • Une branche = un worktree = un sujet. La collision du 17/08 (2 sessions, même worktree) a coûté un commit. Le travail mémoire vit sur brique-1 ; tout le reste part de main.
  • Pousser avant de fermer — un commit local non poussé n'existe pas pour les autres machines.
  • PR en draft, 5 checks verts, merge = Melvyn. Sonar se vérifie après la pose de l'analyse du bon sha.
  • Suivi : ce fichier (mis à jour à chaque jalon) + docs/BACKLOG.md (priorités) + docs/MEMOIRE-CENTRALISEE-ETAT.md (spec mémoire). Une même page, jamais une nouvelle par étape.
