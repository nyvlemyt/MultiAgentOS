Le principe en une image

L'analogie : une recette ecrite. Aujourd'hui le plat se refait de memoire, dans un ordre que seul celui qui l'a deja fait connait. Une recette ecrite, c'est le droit de rater, de recommencer, et de confier le plat a quelqu'un d'autre.

Le manifestela connaissancequel dossier source sert quelle cle, quelles extensions, comment choisir le fichier, a quelle frequence il arrive

Le compte renduune ligne par etapecle, fichier, statut, duree. Jamais une valeur de donnee. Un echec n'arrete pas le passage

Le point dur n'est pas technique, il est de methode : l'assistant ne lit aucune donnee. Le manifeste est donc une declaration que toi seul peux remplir, ligne par ligne, relue dans un diff. C'est le travail long du chantier, et il est incontournable.

Les trois modes, et pourquoi ce n'est pas une liste

Point souleve par Melvyn le 11/09 : il ne faut pas melanger le premier import et les imports reguliers. CSDR apporte une reponse meilleure que deux programmes separes : le mode tombe d'un etat en base. Une table retient ce qui a deja ete ingere, et le mode complet retraite tout simplement parce que cette table est vide. Un seul code, un seul ordre.

ModeQuandCe qu'il joueEtape

Incrementalun flux a un fichier neufl'insertion, puis seulement l'aval necessaire. Inserer trucost_coal_issuer_data ne rejoue aucun referentiel ; inserer jump_issuer_data rejoue issuer, puis asset, puis le proprietaireetape 2

La consequence est structurante : le plan n'est pas une liste plate de 23 etapes mais un graphe avec ses aretes, et l'ordre du bootstrap n'en est qu'un parcours. L'incremental, c'est le meme graphe restreint a la fermeture transitive de ce qui a bouge. Une liste plate aurait oblige a reecrire l'orchestration a l'etape 2 : exactement le truc a la va-vite que tu refuses. L'etape 1 livre le graphe et le bootstrap ; l'etape 2 branche la table de trace et le declencheur, et le graphe les attend deja.
